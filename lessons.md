# Lessons

- No Slack is connected to this repo. After a merge, skip the Slack summary step of `git-shortcuts`. Do not ask for a Slack handle.
- Measure an approximation's error before proposing machinery to avoid it. A worst-case bound derived by hand ("the wave could drift 22px") was 5x the real figure once simulated against measured advances, and the simple version needed none of the timing machinery the bound seemed to demand.
- Corrections to letter fit belong to the gap between two characters, not to a character. Splitting a correction half before and half after a character moves the first one, because it has no partner on its left.
- Do not verify an interpolation only at the points it was fitted to. Freezing the tween at its ten stops showed 0.01px everywhere, because a stop is exact by construction; between two stops the same line was 1.95px out. Sweep the whole range.
- A line that moves is never an acceptable outcome, and neither is a fix that asks the user to keep the weight range, the delay or any other setting small. Holding the line is the whole point of the library, so it is a constraint on the solution, not a thing to trade away. Reaching for JavaScript during the animation is a sign of a wrong model, not a solution: find the simpler one.
- Holding a box is not the same as holding what is drawn in it. A line measured 0.13px steady while its letters moved 4.7px, because the measurement read layout boxes and the eye reads glyphs. Measure the thing that is looked at.
- Layout can carry a signal that no custom property can. Every character needs to know how far over its line is right now, which is a sum across all of them and so cannot be a variable. A flex line computes exactly that sum as its free space and hands it out in equal parts. Reach for the layout algorithm before inventing a clock.
- A handler that answers a hover must read nothing. getComputedStyle, getBoundingClientRect and offsetWidth all work out the waiting styles on the spot, :hover among them, so the tween starts before the handler's own write lands and runs on the value the visit before it left. The symptom reads as a broken detection rule and survives every rewrite of that rule. Measure what a crossing needs beforehand and let the crossing only write.
- A pointer event's offsetX is a page read. It is measured against the target rather than the window, so the browser lays the page out to answer it, which is exactly the forced flush the handler was rewritten to avoid. The rewrite that removed getBoundingClientRect kept offsetX and kept the bug. pageX and clientX are stored on the event and cost nothing, so hold the element's middle in page coordinates and compare against that.
- A test that dispatches its own events proves less than it looks. Synthetic pointer events do not turn :hover on, so no tween starts, so reading the delay afterwards always shows the new value. Three detection rules passed that test and all three failed on a real mouse. Check the thing the user sees, in the state the user is in.
- A `pointerenter` handler cannot set anything the arriving `:hover` will read. The browser turns `:hover` on in the same breath as it dispatches the event, and on the way in the tween has read its `transition-delay` before the handler's write lands, so every entry runs the way the entry before it did. Leaving is fine, which is what makes it look like a detection bug. Five rewrites of the detection rule, then a rewrite that removed the container query in the middle, all kept it. Four rewrites chased the ordering; none of them could win it. The real answer was to have nothing to order. A `transition-delay` latches its value when the tween starts, so every write is early or late; a number the units read in the open, every frame, is neither. One transition per line carries a 0-to-1 wave and each unit works its own progress out of it in `calc()`. The race, the handler's timing, the held departures and the taken-over trigger all went with it. When a value can only be written at the wrong moment, stop writing it at a moment.
- A reversal is already a direction change; asking for another one turns it round twice. The rule reads "out starts at the far end", so the handler aimed at the far end on the way out — but the way out is the same wave running backwards, and backwards already starts at the far end. The two cancelled and the wave came back the way it went. Worse, the flip is read live, so changing it under a half-finished wave jumps every letter at once. State the rule as the wave sees it, not as the eye describes it, and check where a value can change for free: at either end of a wave every letter agrees, so the change is invisible there and only there.
- Read a trace as a whole before theorising about one row. Twelve rows said it in one look: every mismatch was an `in`, every `out` was right, and the wrong value was always the previous crossing's. Individually each row had three plausible explanations; together they had one.
- A style container query settles one style pass after the pass that set the property it queries. Fine for what a stylesheet writes, which is static, and useless for anything a handler writes. Query only what the stylesheet sets; let the script write an inherited custom property the descendants read directly in `calc()`.
- Putting state back is a crossing of its own, and every bug lived in it. Two waves that met at the top had to be run back down to nothing before the next visit, and that whole span was a window where both were mid-flight and neither end could be moved without re-sorting the line. Guards to survive a crossing that landed in it never covered every case. Nothing is put back now: a visit leaves the pair at the far end, the next visit runs them home, and one sign keeps the gap between them the right way up. Three switches, two wait loops and a reset went with it. When the guards keep growing, look for the state they guard and see if it can be got rid of instead.
- A wave running backwards crosses the text the other way. Climbing, it lets go of the shortest wait first; falling, the longest. So the flip that says which end it starts at has to invert with the direction of travel, or the band is laid on back to front. This is the same trap as the double reversal above, one level down: the thing the flip is measured against moved, not the flip.
- An entry that writes a value already in place does nothing, and nothing is indistinguishable from frozen. Two branches, one for a fresh visit and one for a pointer coming back mid-animation, each wrote only the half the other did not need; land in the wrong branch, by one frame of a race over where the waves had got to, and the write was a no-op and the element went dead. Both branches now write both values every time, and the redundant half is the no-op instead. A handler that always states the whole outcome cannot be raced into stating none of it.
- Make the rest state provable, and the race stops mattering. Every entry now sets the leading wave to the far end and the trailing wave home, so the two are always a whole crossing apart and the weight at rest is 1; every leaving sets both to the same end, so it is 0. Hover bolds and leaving unbolds by arithmetic, whatever the waves were doing at the time — the animation only decides how it gets there. Three rounds of guards against particular orderings could not reach that, because they were defending a state that was allowed to be wrong.
- To rewrite prose, give the writer the code and the section headings only, never the old text. An agent that reads the old README or the demo copies its voice, and the voice is what was to go.
- Coding and debugging subagents run on Opus, never Fable, whatever the model table says for hard coding.
- A font's shape does not change smoothly with weight. It is drawn at a few weights and interpolated between them, so the width curve has a corner at every drawing, usually at a multiple of 100. Sampling has to land on those corners, not straddle them.
- Replacing an event library means keeping what the user saw, not only the end state it reached. scrollama passed through every section on a jump, so each nav link waved in turn; a position check that jumps straight to the last section fixed the stuck links and lost the pass-through. List the visible side effects of the old code before swapping it, and test each one.
- Copy the user's wording for display text exactly, odd spellings included. "UGLY INCHIDENT" is an F1 meme, not a typo; correcting it lost the joke. If a word looks wrong, use it as written and ask.
